Sharlie Gate install guide

What to run, what each command writes, how the pieces behave, and what to delete if you stop using it.

What you need

Node.js 24.11 or newer. Check with:

node --version

Sharlie Gate is a local program. It does not create an account and it does not phone home. The editors it can configure are the ones whose folders already exist in your user profile:

  • Cursor
  • GitHub Copilot CLI (~/.copilot)
  • Claude Code
  • OpenAI Codex CLI
  • OpenCode

VS Code and Copilot inside VS Code are optional and only change a project when you pass --legacy-vscode together with --project.

Paths below use your home folder. On Windows that is %USERPROFILE%. On macOS and Linux it is ~. The same commands work on both.

Build it once

From the Sharlie Gate folder:

npm install
npm run build
node dist/sharlie-gate.mjs --version

npm install downloads the libraries this repo lists. npm run build writes dist/sharlie-gate.mjs, dist/tree-sitter.wasm, and dist/grammars/. The version line prints sharlie-gate 0.1.0 when the build is usable.

Later, init copies that program into ~/.sharlie-gate/bin/ so the editors keep a stable path even if you move this folder.

See the changes before they happen

node dist/sharlie-gate.mjs init --dry-run

This prints which editors were found and the full text it would write. It does not change any file. Add the same flags you plan to use for real, for example --project or --with-proxy.

Install

The usual install, for every detected editor:

node dist/sharlie-gate.mjs init

That command does three things:

  1. Copies the program into ~/.sharlie-gate/bin/ (the .mjs file, tree-sitter.wasm, and grammars/).
  2. Writes editor config only for folders that already exist. A missing editor is skipped.
  3. Saves the previous contents of every file it touches in ~/.sharlie-gate/install-manifest.json. If a file already had text, it also writes a sibling .sharlie-gate.bak once.

Add a project when you want rules inside one repository:

node dist/sharlie-gate.mjs init --project C:\path\to\your\repo

On macOS or Linux, use the repo path in that shell, for example --project ~/src/your-repo.

Install remembers the whole file, not a patch. Uninstall later restores each touched file to the bytes from before the first install. Edits you make to those same files after install are included in that restore.

What each editor receives

Every editor entry starts the same local tool server:

node ~/.sharlie-gate/bin/sharlie-gate.mjs mcp

The editor launches that process itself. You do not leave a terminal open for it. The server offers three tools: read_file_outline, expand_section_lines, and targeted_search.

Cursor

Written only when ~/.cursor already exists.

FileWhat running init does
~/.cursor/mcp.jsonAdds an MCP server named sharlie-gate. Other servers in the file stay.
~/.cursor/plugins/local/sharlie-gate/Adds a local plugin: a rule that tells the model to outline first, and a skill with the same instructions.
~/.cursor/settings.jsonAdds sharlie-gate to enabled_plugins.

After init, restart Cursor or reload the window so it picks up the MCP server. In a chat, the model should call read_file_outline before dumping a whole file.

Optional Cursor hooks, which are a separate switch:

node dist/sharlie-gate.mjs init --enforce

That writes ~/.cursor/hooks.json with beforeReadFile, preToolUse, and postToolUse commands. Those commands stay idle until the environment variable SHARLIE_GATE_ENFORCE=1 is set for Cursor. With that variable set:

  • A full read of a file of 150 lines or more is denied, and the model is told to call read_file_outline.
  • A shell command is wrapped as sharlie-gate run -- … so a long transcript is stored and shortened.
  • A huge MCP tool result is cut to the first 2,000 characters.

GitHub Copilot CLI

Written only when ~/.copilot already exists. This is the Copilot CLI home, not the VS Code extension by itself.

FileWhat running init does
~/.copilot/mcp-config.jsonAdds the sharlie-gate MCP server.
~/.copilot/instructions/sharlie-gate.instructions.mdTells Copilot to outline first, then expand a range or symbol.
~/.copilot/skills/sharlie-gate-reader/SKILL.mdSame instructions, packaged as a skill.
~/.copilot/hooks/sharlie-gate.jsonRegisters three hooks. They run on their own. No extra flag.

The hooks do this:

  • userPromptSubmitted remembers files you mentioned with @ so those files are left alone.
  • preToolUse can deny an edit when the session still needs a hidden range expanded.
  • postToolUse replaces a read of 150 lines or more with an outline, and shortens a shell transcript longer than 200 lines.

Claude Code

Written when ~/.claude or ~/.claude.json exists.

FileWhat running init does
~/.claude.jsonAdds the sharlie-gate MCP server. The rest of the file stays.
~/.claude/CLAUDE.mdInserts a marked block between <!-- sharlie-gate:begin --> and <!-- sharlie-gate:end -->. Text outside that block stays.

The proxy switch, described below, is the only install path that also edits ~/.claude/settings.json.

Codex CLI

Written only when ~/.codex already exists.

FileWhat running init does
~/.codex/config.tomlAdds a table [mcp_servers.sharlie-gate] with the node command. Other tables stay.
~/.codex/AGENTS.mdInserts the same marked instruction block used for Claude.

OpenCode

Written only when ~/.config/opencode already exists. If XDG_CONFIG_HOME is set, that directory is used instead of ~/.config.

FileWhat running init does
~/.config/opencode/opencode.jsonAdds a local MCP server named sharlie-gate.
~/.config/opencode/AGENTS.mdInserts the marked instruction block.

One repository

Pass --project with the repo root. These files are written even when the editor home folders are missing:

FileWho reads it
your-repo/.cursor/rules/sharlie-gate.mdcCursor, for this repo only. The rule is always applied.
your-repo/.github/copilot-instructions.mdGitHub Copilot in VS Code and the Copilot CLI, for this repo. The Sharlie text sits inside the marked block.
your-repo/AGENTS.mdCodex, OpenCode, and other agents that read AGENTS.md. Marked block only.

VS Code workspace MCP

node dist/sharlie-gate.mjs init --legacy-vscode --project C:\path\to\your\repo

That also writes your-repo/.vscode/mcp.json with a server entry named sharlie-gate. VS Code and Copilot Chat can start that server for the workspace. The --project files in the table above are written as well.

Optional proxy

The default install does not sit in front of model traffic. The outline tools are enough for the editors above. The proxy is a second program that rewrites chat requests on your machine, on 127.0.0.1:8080 only.

node dist/sharlie-gate.mjs init --with-proxy
node dist/sharlie-gate.mjs proxy

init --with-proxy does two concrete things:

  • If Claude Code is installed, it sets ANTHROPIC_BASE_URL in ~/.claude/settings.json to http://127.0.0.1:8080/anthropic. Claude Code then sends its API calls to the local proxy.
  • It prints an autostart command. It does not run that command, and it does not create a macOS plist or a Linux service file.

proxy keeps running until you stop it. While it is running it can fold older file copies out of the conversation, drop duplicate file views, shorten a resolved error log, trim noisy terminal output, and keep the cacheable prefix of the request stable. A ledger of the savings is stored in ~/.sharlie-gate/ledger.sqlite. Open http://127.0.0.1:8080/ledger in a browser on the same machine to read it.

Stop the proxy by ending that terminal process. Claude Code will fail its API calls while ANTHROPIC_BASE_URL still points at port 8080 and nothing is listening. Run uninstall, or start the proxy again, before you rely on Claude.

If you ran the printed Windows autostart line yourself, logon will start the proxy as scheduled task SharlieGate. Remove that task with:

schtasks /Delete /TN SharlieGate /F

Cursor, Copilot, Codex, and OpenCode are not pointed at the proxy by init. Only Claude’s base URL is.

How a normal session works

  1. The editor starts sharlie-gate.mjs mcp when a chat needs tools.
  2. The instruction files ask the model to call read_file_outline first. Files under 150 lines come back whole. Longer files come back as signatures and line markers, with the bodies hidden.
  3. The model calls expand_section_lines for one hidden range or one symbol, or targeted_search to find a string with a few lines of context.
  4. Before an edit, the model is told to ask for the full file with intent: "edit".
  5. For TypeScript, JavaScript, Python, Go, and Rust, symbol names come from Tree-sitter. Other languages use the built-in scanner. Both paths stay on your machine.

Nothing in that path requires the proxy. Hooks, when present, are a backstop for reads and shell output that bypassed the tools.

Check that it is installed

node dist/sharlie-gate.mjs doctor
node dist/sharlie-gate.mjs status

doctor prints which editor folders it can see, whether the proxy bypass flag is on, and whether node is missing. status prints a one-line savings summary from the ledger. An empty ledger is normal until the proxy has handled traffic.

Turn the proxy’s rewriting off without uninstalling:

node dist/sharlie-gate.mjs bypass on
node dist/sharlie-gate.mjs bypass off

bypass on writes a flag file at ~/.sharlie-gate/bypass. The proxy process must be running for that flag to matter. bypass off removes the flag.

Stop using it

From the Sharlie Gate folder:

node dist/sharlie-gate.mjs uninstall

That command reads ~/.sharlie-gate/install-manifest.json and puts every file init touched back to its previous contents. A file that did not exist before install is deleted. The manifest is then emptied. Editor MCP entries, rules, skills, hooks, and the marked blocks in CLAUDE.md, AGENTS.md, and copilot-instructions.md go away with that restore.

Uninstall does not delete the data folder, the backups, or a scheduled task you created yourself. Do the extra steps below if you want no Sharlie Gate files left.

1. Stop anything still running

  • Close the terminal that is running sharlie-gate.mjs proxy, if you started one.
  • Quit the editors so they are not still holding the MCP process.
  • On Windows, if you created the logon task: schtasks /Delete /TN SharlieGate /F.

2. Run uninstall

node dist/sharlie-gate.mjs uninstall

You should see the single word uninstalled.

3. Delete leftovers by hand

These are not removed by uninstall:

LeftoverWhat it is
~/.sharlie-gate/The whole data folder: the copied program in bin/, install-manifest.json, ledger.sqlite, sessions/, and the bypass flag. Deleting this folder removes the program the editors were pointed at. Do this after uninstall, so the manifest has already been applied.
*.sharlie-gate.bakOne backup beside each config file that already had contents. Examples: ~/.cursor/mcp.json.sharlie-gate.bak, ~/.claude.json.sharlie-gate.bak, ~/.codex/config.toml.sharlie-gate.bak. Delete the .bak files after you are sure the restored files look right. Search your home folder and the project you passed to --project.
This git checkoutnpm install and npm run build only affect the Sharlie Gate folder (node_modules/ and dist/). Delete the checkout if you do not want the source. That does not uninstall Node.

4. Confirm the editors are clear

After uninstall and after deleting ~/.sharlie-gate, these should no longer mention sharlie-gate:

  • ~/.cursor/mcp.json and ~/.cursor/settings.json
  • ~/.cursor/plugins/local/sharlie-gate/ (the folder is removed when it was created by init)
  • ~/.cursor/hooks.json if you used --enforce
  • ~/.copilot/mcp-config.json, ~/.copilot/hooks/sharlie-gate.json, ~/.copilot/instructions/sharlie-gate.instructions.md, ~/.copilot/skills/sharlie-gate-reader/
  • ~/.claude.json, ~/.claude/CLAUDE.md, and ~/.claude/settings.json if you used --with-proxy
  • ~/.codex/config.toml and ~/.codex/AGENTS.md
  • ~/.config/opencode/opencode.json and ~/.config/opencode/AGENTS.md
  • In the repo: .cursor/rules/sharlie-gate.mdc, the marked block in .github/copilot-instructions.md, the marked block in AGENTS.md, and .vscode/mcp.json if you used --legacy-vscode

Restart each editor once so it drops the old MCP process.
